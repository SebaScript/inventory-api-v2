# Rules of engagement — security chaos game day

Agreed before any experiment runs. A game day that steps outside these rules is void.

## Scope

- **Only our own accounts and resources.** API A: the AWS account that Terraform builds
  (`inventory-api-*`). API B: its own Google Cloud project. Nothing of the University, of
  other groups, or of any third party is touched.
- **Synthetic data only.** The bucket holds seed exports and flow messages generated by the
  demo. No real personal or business data exists in this system.
- **Window.** Each round runs inside a scheduled slot, announced in the group chat, with the
  infrastructure already up. Both members know a game day is in progress.

## Experiments (two-person version)

| # | Layer | Owner | Adverse condition |
|---|---|---|---|
| 1 (mandatory) | Machine identity | A | The node role's temporary credentials, read from IMDSv2, are used from **outside AWS** (the GitHub runner) against S3 |
| 4 (minimal) | Data resilience | A runs, B analyses | Ransomware: the `flows/` objects of one bucket are overwritten or deleted |
| 3 | Telemetry + AI | B | Logging degraded and a prompt injected into the AI triage assistant |

Experiment 2 (exposure/segmentation) is out of scope for the two-person version.

## Control hypotheses (falsifiable, one per experiment)

- **Exp 1.** Given the node role as configured today, when its credentials are used from
  outside the VPC, we expect an alert in `/security/alerts` in **≤ 5 min (T1)** and the
  credentials to stop working in **≤ 10 min (T2)**.
- **Exp 4.** Given the bucket as configured today, when the `flows/` objects are overwritten
  or deleted, we expect the previous good version to be recoverable (RPO = time since the last
  good write) with a restore time (RTO) we measure.

Round 0 runs against the controls as they are today (v4.2.0) and is expected to **refute**
these hypotheses (no detection, no recovery). Round 1 runs after the improvements (v4.3.0).

## Stop switch and reversion

- **Stop:** cancel the running GitHub Actions workflow. Every injection is a single step; no
  fault outlives the run.
- **Reversion, verified before round 0:**
  - Exp 1: `gameday.yml exp1-contain` removes the session-revocation policy; the node assumes
    the role again and gets fresh credentials. `terraform plan` shows no drift.
  - Exp 4: `gameday.yml exp4-restore` copies the last good version back. Object Lock is
    *governance* mode, so the end-of-day `terraform destroy` can still remove the bucket.

## Logbook and traceability

- Every adverse act is marked so a third party can reconstruct it: the attack calls carry
  `AWS_EXECUTION_ENV=gameday-exp<N>-r<round>`, which CloudTrail records, and the load that runs
  in parallel to measure false positives carries `x-correlation-id: k6-…`.
- Evidence is timestamped and kept as workflow artifacts and in `/security/alerts` and the
  CloudTrail trail.
- Traceability of each control to ISO/IEC 27001:2022 Annex A and MITRE ATT&CK/D3FEND is in the
  README and in the game-day report.

## Prohibited

Acting on services, accounts, networks or data of third parties, of the University or of other
groups. Weakening the fault/attack switches so they would work without their token or outside a
run. Committing real credentials, tokens or account data.
